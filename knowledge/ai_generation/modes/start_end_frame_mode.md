# 首尾帧模式手册

> 适用范围：提供起始帧与结束帧，让模型生成两者之间的过渡。
> 不适用：需要稳定经过 3 个以上关键节点的复杂段落；那通常更适合分镜图驱动或拆条生成。

---

## 一、适用场景

- 起始构图和结束构图非常明确。
- 需要保证构图变化、机位变化、人物姿态变化或下一镜接点。
- 同一镜头内部完成推进，但中间变化有限。
- 过渡落点比过程细节更重要。

典型：

- 观察 -> 更压迫
- 远一点 -> 更近一点
- 蹲着探头 -> 更前探一点
- 平静站位 -> 手已经抓紧道具

---

## 二、优势与风险

优势：

- 起点与终点可控。
- 适合指定镜头最后停在哪里。
- 比单纯 prompt 更能保证姿态和构图落点。

风险：

- 中间动作可能被简化。
- 起止帧差异太大时，过渡容易跳变。
- 如果角色身份在两帧里差异明显，模型可能重绘身份。

---

## 三、写法规则

必须写清：

- 起始帧承担什么。
- 结束帧必须落成什么。
- 中间只允许发生哪些变化。
- 哪些关系不能变。

结构：

```text
以起始帧作为开场构图：[当前站位/姿态/道具关系]。
在同一镜头内完成有限变化：[谁做什么动作，身体/道具如何变化]。
最后必须落到结束帧的构图与姿态：[明确落点]。
保持：[身份、左右关系、光源方向、关键物位置]。
禁止：[新增角色、提前 reveal、改变道具归属、翻转轴线]。
```

---

## 四、何时不要用首尾帧

- 需要 3 个以上关键节点。
- 中间有复杂因果链。
- setup 与 reveal 区必须强分离。
- 人物需要持续表演而不是有限姿态变化。
- 起止帧本身构图跨度太大，更像两个镜头。

这些情况优先考虑：

- 分镜图驱动
- 双镜头 / multi-shot
- 拆条生成

---

## 五、常见失败与修正

| 失败现象 | 修正 |
|---------|------|
| 只在两帧间硬变形 | 缩小起止差异，拆成两条 |
| 人物身份漂移 | 起止帧用同一角色版本，prompt 强调身份不变 |
| 中间动作缺失 | 补一个明确动作动词和道具受力变化 |
| 终点没落准 | 把结束帧落点写在 prompt 末尾并重复一次 |
