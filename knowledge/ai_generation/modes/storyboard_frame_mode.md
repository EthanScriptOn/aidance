# 分镜图驱动模式手册

> 适用范围：已经有 2 到 4 张成品分镜图，用这些图作为构图锚点生成同一段视频。
> 不适用：直接上传角色图/场景图/道具图做组合生成；那属于 `omnipotent_mode.md`。

---

## 一、适用场景

- 需要稳定落成 2 到 4 个关键节点。
- setup 区与 reveal 区强分离。
- 复杂群像站位一旦漂移就没法用。
- 关键动作桥丢了就看不懂因果。
- 纯文本或全能模式容易改错构图、站位、角色关系。

---

## 二、优势与风险

优势：

- 构图稳定。
- 高风险站位和 reveal 更容易锁住。
- 适合把 Image2 / gpt-image 生成的关键帧动态化。

风险：

- 容易退化成 PPT 式串图。
- 关键帧之间构图差异大时，模型可能只播放几张图。
- 如果只上传成品分镜图，不再上传单独角色图，模型不一定知道图里谁是谁。

---

## 三、防幻灯片规则

分镜图驱动不是“把几张关键帧按时间播放”。关键帧只能作为构图锚点。

关键帧职责：

| 关键帧职责 | 正确用法 | 高风险写法 |
|-----------|----------|------------|
| 构图锚点 | “以 @图片1 的群像站位作为起始构图，人物开始移动/交接/转身” | “前 3 秒显示 @图片1” |
| 动作中段 | “让人物从上一构图做出可见动作，运动到 @图片2 的关系” | “中间 3 秒切到 @图片2” |
| 落点锚点 | “最后落到 @图片3 的姿态和职责关系，停住半秒” | “最后 2 秒自然过渡到 @图片3” |

强制要求：

- 最终 prompt 开头必须说明：生成连续视频动作，不要把参考图当作静态幻灯片依次播放，不要只做图片缩放、平移或轻推镜。
- 每张关键帧后面都必须补一个 `可见动作主语 + 具体身体动作 + 位移/姿态变化 + 结果`。
- 禁止只写“从 @图片1 开始 / 推进到 @图片2 / 过渡到 @图片3”而没有动作桥。
- 如果三张分镜图构图差异很大，应明确写成 `multi-shot coverage`，允许切镜，但每个镜头内部仍必须有动作。

---

## 四、图内人物指认

只上传成品分镜图、不再上传单独角色图时，最终 prompt 必须补 `图内人物指认`。

格式：

```text
图内人物指认：
[角色名] 是 [图中可见外貌特征]，位于 [画面位置/职责]。
[角色名] 是 [图中可见外貌特征]，负责 [动作/关系]。
三张图里的角色名称都按这个指认关系理解，不要重新分配身份。
```

要求：

- 用可见特征绑定角色：年龄、发型、衣服、道具、体型、站位。
- 用职责绑定角色：谁发号施令、谁守绳、谁持枪、谁被留在外围。
- 禁止只写老三、老烟头、老二、大胡子等角色名让模型猜。

---

## 五、标准输出字段

`seedance_storyboard_prompts.md` 中分镜图驱动 Beat 必须包含：

- 目标渲染器
- 建议模型
- 建议模式
- 屏幕尺寸
- 分辨率
- 视频建议时长
- 关键帧时间分配
- frame_continuity_contract：每张关键帧的 `previous_frame_state / start_state / end_state / visible_characters / offscreen_characters / visible_object_state / implied_object_state / next_frame_handoff`
- 台词策略
- 图内人物指认
- 动作桥检查
- 本次上传顺序
- 单次请求直贴 prompt

关键帧时间分配只能写“承担的镜头功能”，不能写静态停留时长。

关键帧连续性规则：

- 每张关键帧必须说明本帧结束时关键道具在哪里、由谁持有、是否已经进入洞口/门内/车内/画外。
- 下一张关键帧必须从上一张的 `end_state` 接起，不得让上一帧提前执行下一帧动作。
- 下一张关键帧也不得撤销上一张已经建立的人物/道具/空间状态；如果状态变化，必须写出可见转移动作。
- 对关键道具必须拆开 `visible_object_state` 与 `implied_object_state`：例如铁钩不可见属于可见状态，绳线仍通向黑洞属于隐含状态，两者不能互相否定。
- 如果上一帧只负责“职责落定 / 接住尾端 / 决定已下”，就不得提前画出“正式下放 / 已经入洞 / 已经交战”等下一拍动作。
- 未上传某角色参考时，不得允许该角色以局部手脚、背影、影子或边缘暗示入画；需要可见局部就必须上传对应人物参考，否则改成画外压力、道具受力、视线反应或负空间。

正确：

```text
@图片1 作为起始 master 构图：人物开始重排
@图片2 作为动作中段构图：职责被压给角色
@图片3 作为落点构图：职责关系停住半秒
```

高风险：

```text
@图片1 约 3s
@图片2 约 3s
@图片3 约 2s
```

## 六、单次请求 prompt 结构

```text
把这 N 张分镜图当作同一段视频的构图锚点，生成连续视频动作，不要把它们当作静态幻灯片依次播放，不要只做图片缩放、平移或轻推镜。

图内人物指认：[角色名 = 可见特征 + 位置/职责...]

Shot 1 以 @图片1 的构图开场：[谁先动，身体哪里动，站位/道具如何变化，结果是什么]。

Shot 2 切到 @图片2 的关系：[谁继续动作，谁反应，动作如何推进到新的关系]。

Shot 3 落到 @图片3 的职责/后果：[谁停住，谁不能做什么，最后关系是什么]。

禁止：[不翻左右，不混身份，不提前 reveal，不让角色开始下一拍动作]。
```

## 七、何时切换策略

切换到首尾帧：

- 只有起点和终点重要，中间过程不复杂。
- 分镜图多了反而导致 PPT。

切换到行为起始帧：

- 核心问题是人物不动。
- 已有一张最有动势的关键帧。

拆条生成：

- 同一段里动作阶段太多。
- 需要剪辑节奏，而不是单条视频完整承载。

---

## 八、已验证经验

Beat04 实测：

- 原问题：三张分镜图生成视频像 PPT，人物基本不动。
- 有效修法：`图内人物指认 + multi-shot coverage + 动作桥检查`。
- 结果：人物动作明显增强，不再只是静态切图。

对应复盘详见 `knowledge/ai_generation/video_field_test_findings.md`。
