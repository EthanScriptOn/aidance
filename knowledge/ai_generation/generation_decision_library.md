# AI 视频生成决策总览

> 专业归属：AI 视频导演 / 技术分镜。
> 用途：只负责“该用哪种生成策略”的公共决策，不承载某个具体模式的细则。确定模式后，必须进入 `modes/` 下对应模式手册。

---

## 一、公共知识范围

这些规则适用于所有生成策略：

- 先判断镜头目的，再决定输入能力 / 控制方式。
- 先判断场景的镜头组织形式，再决定控制方式与镜头拆分。
- 镜头语言不等于单条 prompt，很多“电影感”来自镜头之间的关系。
- 当问题不是“文案写不好”，而是“控制手段不够”时，应切换策略，而不是继续加形容词。
- 当前常用模型最短生成时长若为 `4s`，应优先让镜头承担明确事件点，而不是纯状态维持。
- 先查 `video_field_test_findings.md`；实测经验与理论策略冲突时，以同类实测经验为准。

公共决策顺序：

1. 判断这拍是状态型还是事件型。
2. 如果只是状态，先改写成功能关系。
3. 选择镜头落地桶：单镜头、multi-shot、insert + reaction、POV + reaction、reveal、montage。
4. 选择输入能力：全能模式、单张行为起始帧、首尾帧、分镜图 + 文本。
5. 进入对应模式手册。
6. 最后才决定模型与渲染器写法。

## 二、非公共知识范围

这些规则不得混写在总览里，必须归入对应模式手册：

| 具体规则 | 所属模式手册 |
|---------|-------------|
| 多图参考上传顺序、人物/场景/道具 `@` 锚定 | `modes/omnipotent_mode.md` |

| Seedance / Kling 最终输出格式 | `model_renderer_playbooks.md` |
| 真实测试成功/失败条件 | `video_field_test_findings.md` |

## 三、能力层 / 控制方式

| 能力 / 方式 | 最适合 | 优势 | 风险 | 细则 |
|------|-------|------|-----|-----|
| 全能模式 | 场景搭建、角色一致性、小动作镜头 | 方便组合角色图、场景图、道具图 | 人物和场景都锁得太死，动作弱 | `modes/omnipotent_mode.md` |
| 单张行为起始帧 | 需要人物真的动起来的镜头 | 最利于主体动作和微表演 | 需要先有一张合适的行为图 | `modes/action_start_frame_mode.md` |
| 首尾帧 | 明确知道从哪到哪的过渡镜头 | 对构图落点和过渡最可控 | 需要准备两张关键帧 | `modes/start_end_frame_mode.md` |
| 分镜图 + 文本 | 已有明确镜头构图，需要动态化 | 构图稳定，适合高风险站位与 reveal | 容易僵、像 PPT、镜头感受限 | `modes/storyboard_frame_mode.md` |

规则：

- 不要把模型名当成能力名来写。
- 应先判断“这拍用哪种能力”，再决定“用哪个模型去跑”。

## 四、镜头功能判断

### 1. 状态型镜头

定义：

- 人物只是在看、听、蹲守、发呆、沉思、站着。
- 镜头里没有清楚的动作转折点。

风险：

- 4 秒里容易发呆。
- 模型只能给轻微呼吸、轻微推镜、轻微抖动。

处理原则：

- 不要默认独立做成长单镜头。
- 优先改造成：
  - 观察 -> 被信号击中
  - insert -> reaction
  - POV -> reaction
  - Shot 1 建立 + Shot 2 更近反应

### 2. 事件型镜头

定义：

- 镜头里有清楚变化点。
- 观众能说出“这 4 秒里发生了什么”。

例如：

- 听见一声动静后手收紧
- 枪卡壳
- 道具落地
- 眼神突然锁住
- 怪物从暗处显形
- 回头后看见异常

处理原则：

- 更适合单镜头独立生成。
- 也可作为双镜头或 multi-shot 中的一拍。

## 五、4 秒最小生成时长下的第一判断

当模型最短只能生成 `4s` 时，先不要急着决定：

- 用全能模式还是首尾帧
- 用单镜头还是 multi-shot
- 用可灵 omni 还是 Seedance 2.0

先判断这 `4s` 里到底应该发生哪一种功能关系。

优先功能关系：

- `insert -> reaction`
- `POV -> reaction`
- `reveal -> reaction`
- `action -> aftermath`
- `setup -> payoff`
- `观察 -> 被信号击中`

禁止默认做法：

- 一个纯状态镜头直接硬撑 `4s`
- 因为模型最低 `4s`，就机械地把所有镜头都写成 `Shot 1 + Shot 2`
- 还没决定叙事功能，就先决定全能模式 / 首尾帧 / 模型名

## 六、按落地方式分桶

### A. 适合单镜头直接生成

适合：

- 异常细节镜
- 道具 insert
- 单一动作起手
- 小范围动作爆发
- 简单 reaction
- 已有明确动作的行为起始帧镜头

建议：

- 优先全能模式或单张行为起始帧。
- 若模型最短 `4s`，中段信息最重要，前后留剪辑余量。

### B. 更适合双镜头 / Multi-Shot

适合：

- 观察 -> 压迫
- 平静 -> 绷住
- 远一点 -> 近一点
- 先看空间 -> 再看表情
- 先看动作 -> 再看反应

### C. 更适合 Insert + Reaction

适合：

- 关键物件揭示
- 伤痕 / 道具 / 绳索 / 帛片 / 手部
- “看见某物 -> 被击中”

### D. 更适合 POV + Reaction

适合：

- 惊吓发现
- 偷看
- 弥留视角
- 林地里回头见怪物
- 洞里忽然传来异常

### E. 不适合直接整段喂给模型

常见类型：

- 长时间沉思镜
- 纯等待镜
- 复杂的“先静后压迫再推进再表情变化”
- 同时要求不走、不转头、不站起、还要持续紧张

处理原则：

- 拆
- 改事件点
- 改成 insert / reaction
- 改成 POV / reaction
- 改成双镜头

## 七、实操判断表

| 你要做的镜头 | 优先策略 | 进入手册 |
|-------------|---------|---------|
| 人物在场景里建立关系，轻微动作 | 全能模式 | `modes/omnipotent_mode.md` |
| 人物原地观察，但要明显微表演 | 单张行为起始帧 或 双镜头 | `modes/action_start_frame_mode.md` |
| 需要从一个构图过渡到另一个构图 | 首尾帧 | `modes/start_end_frame_mode.md` |
| 想要更强电影感但单镜头总发死 | 双镜头 / Multi-Shot | 本手册 + coverage 库 |
| 分镜图已经很好，只要动态化 | 分镜图 + 文本 | `modes/storyboard_frame_mode.md` |
| 分镜图生成视频像 PPT，人物几乎不动 | 改首尾帧 / 行为起始帧 / 拆片段；如继续分镜图，重写动作桥 | `modes/storyboard_frame_mode.md` |
| 紧张对话或对峙 | Master + Coverage / Shot-Reverse-Shot | coverage 库 + 对应模式 |
| 关键道具或细节揭示 | Insert + Reaction | 对应模式 + 经验库 |
| 惊吓发现 | POV + Reaction | 对应模式 + coverage 库 |
| 时间压缩 / 记忆 | Montage + 剪辑 | coverage 库 |

## 八、给 planner / storyboard 的强制提醒

- 遇到“等待 / 观察 / 沉思”类镜头，先问：这是状态，还是事件？
- 如果答案是“状态”，默认不要直接写成长单镜头。
- 当前模型下，宁可多一刀切镜，也不要让一个没有事件点的状态镜头硬撑 4 秒。
- 当单镜头连续两次测试都只出现“人物微动 + 画面轻推”时，不要继续堆 prompt，必须改策略。
- 决定某个具体模式后，必须进入对应 `modes/` 手册，不得把其他模式的专属规则混入当前 prompt。
